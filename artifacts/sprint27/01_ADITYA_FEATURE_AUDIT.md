# Sprint 27 — Aditya-L1 Feature Pipeline Audit (Q1)

**The single finding that most constrains Aditya-L1 utility: the two instruments enter the model as 22 raw, unnormalized, heavily duplicated instantaneous channel values with zero feature engineering, while GOES enters with 12 physics-engineered temporal features — and the repository's own information-gap audit proved that engineered temporal features are where nearly all GOES skill lives.** Everything downstream (masking, fusion, training exposure) compounds this, but no fusion mechanism can recover dynamics and history that were never computed.

## Feature flow, end to end (every step cited)

1. **Raw processing.** Daily instrument parquets are resampled to the 1-minute GOES grid in `scripts/build_multi_instrument_dataset.py`: rates by mean, counts by sum (`scripts/build_multi_instrument_dataset.py:48-50`). SoLEXS raw spectral universe (`solexs_sdd2_spec_counts_ch13…ch37`, 340 spectra features) and the HEL1OS universe (CZT/CdTe lightcurves, spectra, events, housekeeping — 2,109 audited features total per `artifacts/aditya_l1/stability_adjusted_signal_audit.json` metadata) are compressed to the 22 model features named in `artifacts/feature_columns_v3.json`: `solexs_rate_ch1…ch9`, `solexs_counts_ch1…ch9`, `hel1os_rate_band0/band1`, `hel1os_counts_band0/band1`. The mapping from raw bands to `band0`/`band1` is `NOT PROVEN` from the files read this session.
2. **Temporal alignment.** A left merge onto the GOES 1-minute timestamp grid (`build_multi_instrument_dataset.py:108`). No interpolation; unmatched minutes become NaN, then **zero** (`:126` `fillna(0.0)`, repeated at load in `app/services/ml/dataset_v3.py:67`). Alignment therefore *occurs* at the grid level but *fails* at the semantic level: a missing minute and a zero-count minute are byte-identical to the model, and the real-data manifold never touches zero (available `solexs_rate_ch1` spans 150 → 8,766; counts 750 → 134,030 — computed this session on `artifacts/sprint14c/s2_val.parquet`).
3. **Masking.** Per-minute availability masks are correctly created in the builder (`build_multi_instrument_dataset.py:114,120`) — then **collapsed to a single scalar per window sampled at the label minute** in `app/services/ml/dataset_v3.py:110-111` (`m_s = self.mask_solexs[idx + self.seq_len]`). With SoLEXS available only 75.60% of Stage-2 validation minutes (computed this session), roughly a quarter of the timesteps inside "available" windows are silent zero-fill the model cannot distinguish from data.
4. **Normalization.** None exists anywhere in the V3 path for Aditya features — no scaler, no log transform (repository-wide grep this session; the only `StandardScaler` hits are `scripts/cluster_model_errors.py:89` and `scripts/train_baseline.py:71`, both unrelated). GOES at least carries `log_long_flux`; SoLEXS/HEL1OS counts spanning three orders of magnitude hit the linear patch embedding raw.
5. **Feature engineering.** None for Aditya-L1. GOES gets rolling means/variances, peaks, gradients, accelerations, and `minutes_since_last_flare` (`artifacts/feature_columns_v3.json` goes list; computed in `app/services/ml/features.py`). No SoLEXS or HEL1OS gradient, ratio, rolling statistic, or history feature exists anywhere in `app/` or `scripts/` (grep this session). `artifacts/information_gap_report.json` shows removing GOES's engineered/history features collapses True Skill Score to 0.0 — the feature class proven to carry the skill is exactly the class Aditya-L1 was never given.
6. **Model entry and asymmetry.** Each instrument gets its own patch embedding, positional encoding, encoder stack, and attention pooling (`app/services/ml/model_v3.py:184-222`). Treatment is deliberately asymmetric: GOES 4 layers × 128-dim (`:156,159`), SoLEXS and HEL1OS 5 layers × 160-dim (`:157-158,160-161`) — the *larger* encoders are assigned to the *weaker, rawer* inputs, and (see 8) the ones trained on the least real data.
7. **Missing-token application.** The learnable missing tokens exist only at the pooled-embedding level: `e_solexs = e_solexs_raw * mask + missing_token * (1 - mask)` (`model_v3.py:322-323`, HEL1OS `:349-350`). Because the mask is the window-scalar from step 3, the token substitutes whole windows only; intra-window gaps pass through as zeros.
8. **Training exposure.** Stage 1 (2010–2022, 5.16M windows) freezes the SoLEXS/HEL1OS branches (`app/services/ml/trainer_v3.py:62-82` `set_encoder_frozen`; Stage-1 GOES-only pretraining per `artifacts/sprint14c/experiment.log`) — correctly, since their columns are fabricated zeros pre-2023 (`build_multi_instrument_dataset.py:116,122`). Consequence: the Aditya encoders received gradient updates only on Stage 2's 785,938 windows (~18 months) while the GOES encoder saw 16 years.
9. **Fusion to logit.** Each instrument is pooled to one vector (`model_v3.py:294-296, 314-316, 341-343`), SoLEXS/HEL1OS projected 160→128 (`:357-358`), stacked as a 3-token sequence, mixed by a single 4-head self-attention layer (`:359-363`, `fusion_attn` defined `:225`), flattened to 384 and mapped by one linear head (`:366-369`, head defined `:228`).

## Where information is lost (ranked)

| # | Loss point | Mechanism | Citation |
|---|-----------|-----------|----------|
| 1 | No engineered dynamics/history for Aditya-L1 | Raw instantaneous values only; the proven-dominant feature class absent | `artifacts/feature_columns_v3.json`; `artifacts/information_gap_report.json` |
| 2 | Redundant inputs consume capacity | rate↔counts r=0.85–0.87 (SoLEXS) and 0.95–0.96 (HEL1OS); HEL1OS band0↔band1 r=0.9911 (computed this session) — ~22 columns ≈ 2–3 independent signals | this session's computation on `s2_val.parquet` |
| 3 | Zero-fill conflates absence with quiet sun | 24.4% of Stage-2 validation minutes zero-filled inside windows | `build:126`, `dataset_v3.py:67`, availability computed this session |
| 4 | Window-scalar mask at the label minute | Per-minute masks discarded at load | `dataset_v3.py:110-111` vs `build:114,120` |
| 5 | No normalization/log scaling | 10²–10⁵ raw counts into a linear patch embed | grep this session; ranges computed this session |
| 6 | Single-vector-per-instrument pooling before fusion | Temporal axis destroyed pre-fusion; lagged cross-instrument relations unrepresentable (see `05_FUSION_LIMITATIONS.md`) | `model_v3.py:294-296,359-369` |
| 7 | Encoder under-training | Aditya branches: 18 months of gradients vs 16 years for GOES | `trainer_v3.py:62-82`; `artifacts/sprint14c/experiment.log` |
