# ADR-0020 — Gates fail closed

## Context

A gate that did not run is indistinguishable from a gate that passed, unless the system
treats the two differently. This project has already lost a full test suite to a guard that
silently skipped, and lost four days of red CI to a workflow whose failure had no
destination.

## Decision

- Every required check runs on every pull request and every push to the default branch,
  with **no path filters**. A required check that never reports blocks the merge.
- A gate that cannot execute **fails**. It never passes by default.
- Every gate has a **deliberate-violation test** proving it fails when it should.
- Gate reports enumerate what was checked, not only what failed.

## Consequences

- CI is slower than a path-filtered configuration. At sub-minute jobs this is irrelevant.
- A false pass is a Severity-1 finding (VVMP §8.4).

## Verification

INTG and INSP per VVMP §2.1: a no-path-filter test, and per-gate violation tests.
