# ADR-0011 — Instrument declaration and gate

## Context

A prior generation of this project shipped a feature named for one instrument that consumed
another. The dependency was **declared correctly in the class metadata** and no gate ever
read it, so an "Aditya-only" model was in fact driven by a GOES channel correlating -0.9151
with the label-generating flux.

Declared metadata that nothing enforces is decoration.

## Decision

Every MethodRelease declares the instruments it consumes, machine-readably. Every Protocol
declares which instruments are permitted.

At execution the engine asserts `declared_instruments ⊆ permitted_instruments`. On mismatch
it **refuses to score** and records a PolicyRejection naming the gate.

## Consequences

- The specific historical failure is structurally prevented, not merely documented.
- A method consuming an undeclared instrument cannot be scored at all.

## Verification

INTG per VVMP §2.1. The verification artifact is a **regression test reproducing the v1
failure**: a method declaring a GOES input is rejected by an Aditya-only protocol. This test
is a required CI check.
