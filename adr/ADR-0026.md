# ADR-0026 — Context map

## Context

An earlier map defined nine bounded contexts, most with a single instance, for one
maintainer. That violated the two-instance principle at the level of the map itself.
Separately, Provenance has no domain behaviour of its own — it is vocabulary — and calling
it a context was a category error.

## Decision

**Provenance is a shared kernel**, not a bounded context. Six bounded contexts remain, each
defending an invariant that would be lost on merge:

| Context | Invariant defended |
|---|---|
| **Ingest** | External formats and credentials never escape |
| **Curation** | Releases are immutable and never optimised for the benchmark |
| **Ground Truth** | Labels are exogenous and revisable |
| **Method** | Cannot reach test labels |
| **Evaluation** | Depends on contracts only; never imports a method |
| **Evidence** | Read-only; renders nothing unbound |

Acquisition and Canonicalisation are merged into **Ingest**, with the seam preserved as
module boundaries — which is free under [ADR-0025](ADR-0025.md). They split again when a
second source exists. Evidence and Publication are merged into **Evidence**.

Dependency rules: the kernel imports nothing; `domain/` imports stdlib only; Evaluation
imports contracts and domain only; Evidence writes nothing; no context imports another
context's internals.

## Consequences

- Fewer boundaries to erode under solo-maintainer pressure.
- Splitting Ingest later is a module move, not a redesign.

## Verification

ARCH per VVMP §2.1: a kernel-zero-imports test plus six import-direction tests, each with a
deliberate-violation case.
