# ADR-0019 — Monorepo, contracts as vocabulary

## Context

One team, tightly coupled contracts, atomic cross-context changes, one CI. Polyrepo would
buy independent deploy cadence for components that do not deploy independently.

Every `common/`, `shared/`, `utils/` and `core/` package eventually becomes a dependency-cycle
laundering service.

## Decision

A single repository. The **only** cross-context vocabulary is `contracts/`, expressed as
normative JSON Schema.

Directories named `common`, `shared`, `utils`, `core`, `misc`, `legacy` or `archive` are
forbidden at any depth.

Schemas are normative; language types are hand-written and validated against them.

## Consequences

- Cross-context changes are atomic and reviewable in one diff.
- Contract changes are deliberately expensive, which is the point.

## Verification

ARCH per VVMP §2.1: a cross-context import test, and a forbidden-directory-name test.
