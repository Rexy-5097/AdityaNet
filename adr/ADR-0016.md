# ADR-0016 — Sandboxed method execution

## Context

Accepting third-party code for execution is a trust boundary, not merely an API. A design
built around in-process import cannot later be sandboxed without redesign, because the wire
format is the part that must exist first.

## Decision

Method execution crosses a **serialised wire format**. Third-party method execution is
out-of-process, network-denied, and resource-limited.

## Consequences

- The wire format is defined at inception; all methods, including first-party, are invoked
  through it.
- **The isolation infrastructure is not yet built.** Until it is, first-party methods run
  in-process through the same serialised interface, and the security property of this ADR is
  **not demonstrated**.

## Verification

PARTIAL. Wire-format conformance is verified by INTG. **The isolation property is recorded
as UNVERIFIABLE in VVMP §10.2 (U-1) and must not be claimed in published material until it
is built and tested.**
