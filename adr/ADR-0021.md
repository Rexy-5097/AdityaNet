# ADR-0021 — Environment is a pinned evaluation input

## Context

[ADR-0009](superseded/ADR-0009.md) asserted that an Evaluation is a pure function of four
inputs. That claim was false. Results also depend on library versions, BLAS implementation,
thread count, reduction order and CPU architecture. Pinning determinism in a *standard* does
not make the environment an *input*, and an unpinned input means the central invariant is
unenforceable.

This project has already been bitten by the same class of error one level down: a single
lockfile served two environments at two points in history, and only the first was hashed.

## Decision

Evaluation identity is a function of **five** digest-addressed inputs:

    Evaluation = f(MethodRelease, DatasetRelease, LabelRelease, Protocol, EnvironmentRelease)

**EnvironmentRelease** pins: interpreter version, dependency lockfile digest, BLAS/LAPACK
implementation and version, thread counts, hash seed, and container image digest where used.
It **records but does not pin** the platform (OS, CPU architecture).

Every Evaluation declares a **reproduction class**:

- `EXACT` — five inputs and platform match. Guarantee: bit-identical scores.
- `EQUIVALENT` — five inputs match, platform differs. Guarantee: scores agree within the
  tolerance declared by the Protocol.
- `UNREPRODUCIBLE` — any input unpinned. **May not be published.**

## Consequences

- Cross-architecture bit-identity is **not** claimed, because it is not true.
- `EQUIVALENT` requires two platforms to demonstrate; recorded as PARTIAL in VVMP §10.2 (U-2).

## Verification

PROP and INTG per VVMP §2.1: identical-five-inputs yields identical scores; a changed
environment digest yields a distinct evaluation identity.
