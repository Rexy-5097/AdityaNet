# L-11 — Pre-bitemporal observations carry no ingest time

> **Authored, not migrated.** L-01 … L-10 are carried verbatim from
> `artifacts/v2/ml/DATASET_LIMITATIONS_FOR_ML.md`, a dated scientific report. This clause has
> no such source: it states the consequence of [ADR-0022](../../adr/ADR-0022.md), a decision
> that postdates that report. The distinction is recorded rather than blurred, because a
> reader is entitled to know whether a caveat was measured or reasoned.
>
> Cite this clause by ID; do not restate it ([ADR-0013](../../adr/ADR-0013.md)).

**Statement.** Every Observation records `valid_time` — when the phenomenon occurred — and
`ingest_time` — when this system learned it ([ADR-0004](../../adr/ADR-0004.md)).
Observations canonicalised before bitemporal capture began record only `valid_time`. For
these, `ingest_time` is `NULL`, and `NULL` has exactly one meaning: *unknown — this
observation predates bitemporal capture.* It is never fabricated, defaulted, or inferred
([ADR-0017](../../adr/ADR-0017.md)).

**Why it is not backfilled.** A plausible migration would have written the dataset freeze
timestamp into the empty field and marked it imputed. That would fabricate a provenance
value on the field the provenance system depends on most, and a label does not convert a
fabrication into a measurement. The honest value for an unknown time is no time.

**Constrains evaluation — severely.** For an observation with `ingest_time = NULL`, the
system cannot establish what was known at any given moment. The leakage gate — which
rejects a prediction consuming an observation the system had not yet received — is therefore
**unenforceable** over these rows. It is not weakened, not approximated, and not applied
optimistically: it is inapplicable, and the Evaluation records that it was not applied.

**Constrains claims.** No forecasting claim may rest on pre-bitemporal observations. A
Protocol declaring `requires_bitemporal: true` **excludes** them, so the exclusion is
structural rather than a matter of analyst discipline. A Protocol declaring
`requires_bitemporal: false` may use them, and its Evaluation carries
`leakage_gate_applied = false` so that any reader can see which guarantee was in force.

**Does not constrain.** Retrospective detection and nowcasting on the frozen archive, where
the as-of time is definitionally the valid time. There is no future information to leak into
a claim about the minute being observed, so the absence of `ingest_time` costs nothing
there. This is the majority of the platform's published work, and stating the limitation
without stating its boundary would overstate it.

**Scope.** The number of affected observations is **not yet determined**. Bitemporal capture
has not begun, so the boundary between pre- and post-bitemporal rows does not yet exist. The
count becomes measurable at the dual-write stage of the migration
([ADR-0027](../../adr/ADR-0027.md), Stage 1) and must be published then. No estimate is
offered here, because an estimate of an unmeasured quantity is exactly the kind of figure
this platform refuses to print.

**Discharge condition.** This clause narrows, but does not disappear, as post-bitemporal data
accumulates: rows recorded after capture begins are fully governed by the leakage gate. It
can be retired only if every pre-bitemporal observation is superseded by a rebuild that
establishes a genuine `ingest_time` — which, for archive data already acquired, is not
possible. It should therefore be expected to remain in force indefinitely.
